## 一、项目定位

FinMAS 是一个面向中国 A 股宏观政策事件与行业收益预测的多智能体金融分析系统。系统并不只做方向预测，而是围绕“事件为什么会发生、会通过什么路径传导、行业会因此涨跌多少、尾部风险有多大、风险来自哪里”这条完整链路进行建模。它的主系统负责事件机理推理、信息检索、时序预测和方向修正；FinMAS-Risk 则负责把预测结果和真实市场数据转化为可审计、可解释、可监控的风险视图。

这个项目不是单纯调用一个大模型回答问题，而是把 LLM 推理、知识图谱、向量检索、深度学习时序模型、概率校准、风险计量和压力测试组合成一个闭环。它最强调的一点是：所有实验结果都不能偷看未来数据。任何历史信息、标签、市场数据和新闻文档，都必须严格限定在事件发生日之前，否则预测准确率再高也不具备实际风控意义。

## 二、主系统 FinMAS 的 STAR 叙述

### Situation

在中国 A 股市场，宏观政策和重大事件经常在短时间内对特定行业产生显著冲击。传统做法通常只依赖历史行情做时间序列预测，或者只让大语言模型基于常识判断行业涨跌。前者难以理解“政策事件”这类低频但高影响的外部信息，后者则容易产生主观偏差、无法保证证据可追溯，并且一旦在训练或评测中混入未来信息，就会得到被高估的准确率。

这个项目需要回答一个更严格的问题：如果只给系统事件发生日之前能看到的信息，它是否仍然能够解释事件传导机制，并在事件发生后的一段时间内给出有参考价值的行业收益预测和风险判断。同时，系统还要能说明预测错误和风险暴露来自哪里，而不是只给出一个涨跌符号。

### Task

我要做的是构建一套端到端的多智能体金融事件分析系统。它需要完成四件核心任务：第一，把自然语言事件转化为可解释的机理链；第二，在严格时间防火墙下检索和引用历史证据；第三，结合 LLM 推理和深度时序模型给出行业收益预测与区间估计；第四，把预测结果进一步转化为事件级、行业级和组合级风险指标。

评价标准不是简单看模型是否“会跑”，而是看系统是否能在不泄漏未来数据的前提下稳定运行，是否能把收益预测、方向判断、区间覆盖、回撤风险、尾部风险和风险来源完整输出，并且是否具备可复现、可审计和可扩展的能力。

### Action

在系统架构上，我采用“机理 Agent + 数据 Agent + 风险层”的分层设计。机理 Agent 负责处理事件文本和证据，数据 Agent 负责处理时间序列，风险层负责把前两者的输出统一成风控视角。每个事件从输入到输出都经过 walk-forward 时间防火墙，确保所有模型只能使用事件发生日之前的数据。

机理 Agent 的核心是 RAT 与知识图谱的结合。对于一个政策事件，系统不会一次性让模型生成结论，而是沿着“社会层面、行业层面、公司层面、资产层面”这条传导链逐步推理。每一步推理都先经过检索器获取事件日前可见的文档，再从知识图谱中提取相关实体和路径，然后让大模型在当前证据约束下生成本步的推理结论、证据编号、置信度、影响方向和影响幅度。这样做的好处是，最终输出不仅是一个涨跌判断，而是一条可检查、可追溯、可回看的因果链。

RAG 层使用 BGE 中文向量模型和 FAISS 进行稠密检索，同时结合 BM25 和知识图谱信息，对事件库中的文档做时间过滤。这个时间防火墙并不是简单的开关，而是分三层：第一层保证历史先验只使用事件日之前的样本；第二层保证训练和预测永远不读取方向标签；第三层保证检索器只暴露事件日前发布的文档。这样即使未来某一天把更多文档加入语料库，系统也不会因为语料版本变化而出现前视偏差。

数据 Agent 采用 Informer 和 KF-Transformer 双分支结构。Informer 负责长序列特征提取和点预测，KF-Transformer 负责对预测不确定性进行状态空间建模，最后通过门控融合得到统一的点预测和区间。系统还使用 Conformal Prediction 对区间进行事后校准，使 80% 和 95% 区间尽量符合名义覆盖水平。为了让批量实验可以并发运行，我把标准化逻辑改为事件本地计算，避免多个事件共享全局 scaler 导致结果互相污染。

在 LLM 接入层，我统一了 DeepSeek 和本地 Ollama 的调用接口。系统可以根据环境变量自动识别使用哪种模型，并对 API Key 做 ASCII 清洗，避免复制密钥时混入隐藏字符导致请求头编码失败。批量实验通过线程池实现多场景并发，同时保证日志写入和 CSV 落盘在多线程下仍然正确。

在信号融合上，系统会比较纯时序模型的方向判断和 LLM 机理推理的方向判断。如果两者一致，说明模型和外部逻辑相互印证；如果两者分歧，系统会把这种分歧作为重要特征记录下来，并在最终修正中结合事件类型、行业敏感性和历史先验进行有限度的调整。这样既不会让 LLM 完全覆盖时序模型，也不会让一个不稳定的外部信号随意翻转预测方向。

为了进行诚实评估，我把 benchmark 从原始 168 个场景扩展到 321 个事件-行业场景。每个场景都在严格 walk-forward 模式下运行，事件日之前没有任何方向标签和未来文档进入模型。实验在 RTX 5090 GPU 上完成，LLM 使用 DeepSeek V4 Flash，批量脚本支持 4 并发和断点续跑。

### Result

最终 321 个场景全部成功完成，没有失败样本。系统在严格不泄漏未来数据的条件下取得了 51.09% 的 CAR 方向准确率。这个数字虽然低于有信息泄漏时的 61.90%，但明显高于此前留一法基线 47.62%，说明系统在更诚实的评测框架下仍然保留了有效信息。分事件类型看，市场事件和地缘事件的方向判断能力更强，而货币政策、资本市场政策和行业政策类事件更难预测，这也说明单纯依赖政策文本仍然不足以稳定判断短期行业收益。

更重要的是，系统输出的不只是准确率。每个事件都能得到点预测、95% 区间、关键时点方向、回撤、尾部风险和风险区间。这些输出构成了后续 FinMAS-Risk 风控分析的基础。

## 三、FinMAS-Risk 的 STAR 叙述

> `【FinMAS-Risk / 风控中心实习】`

### Situation

在金融科技风险监控中心，风险控制部门关心的不是“这个事件明天涨还是跌”这种单一判断，而是“如果看错会亏多少、最大回撤可能到哪里、哪些行业和事件会带来最大损失、组合是否过度集中、压力情景下是否会被击穿”。原始的 FinMAS 主系统虽然已经输出了事件级风险，但还缺少行业级和组合级视角，也没有压力测试、风险限额、风险归因和可交付报告。

因此，风控中心需要在不重新训练模型、不再跑一遍两小时全量实验的前提下，基于已经完成的 321 场景实验 CSV 和原始市场数据，构建一套离线风险分析服务。这个服务不仅要能算风险，还要能解释风险、定位风险来源，并输出适合业务和审计使用的结构化报告。

### Task

我的任务是在原有系统之上新增 FinMAS-Risk。它需要完成三类工作：第一，把事件级预测风险聚合成行业级和组合级风险；第二，用多种风险计量方法估计 VaR、ES 和最大回撤，并对原有风险预测进行严格回测；第三，增加压力测试、收益归因、风险归因、限额监控和自然语言点评，最终通过 JSON、CSV、HTML 和 FastAPI 输出。

这个模块还有一个重要约束：不能依赖重新训练模型。它必须直接复用现有实验 CSV 和原始行情数据，因此计算过程要轻量、可解释、可复现，并能在几秒到几分钟内完成报告生成。

### Action

FinMAS-Risk 首先通过数据加载层把实验 CSV、行业日线、沪深 300、LPR、融资余额和行业估值数据统一对齐。行业日线用于计算真实行业收益和波动，沪深 300 用于计算市场 beta 和压力情景，LPR 和融资余额用于后续利率与流动性压力测试，估值数据用于第二阶段的因子增强。所有数据都按事件日期和行业代码对齐，避免跨行业、跨时间错配。

在风险计量上，我实现了可切换的风险模型，包括历史模拟、Bootstrap、参数正态法、EWMA、极值理论和模型区间方法。不同方法可以互相比较，避免只依赖单一假设。风险期限覆盖 T+1、T+5 和 T+20，置信水平覆盖 5% 和 1%。组合风险不是简单对事件风险取平均，而是先根据外部权重或等权配置得到行业权重，再从行业日收益构建组合收益序列，然后统一计算 VaR、ES、回撤和集中度。

风险校准部分使用 Kupiec POF 检验判断违约频率是否与理论水平一致，使用 Christoffersen 检验判断违约是否出现聚集，使用 Pinball Loss 评估分位数预测质量，并用 Bootstrap 生成违约率置信区间。同时，我把预测最大回撤和真实最大回撤之间的平均绝对误差纳入校准，因为对于风控中心来说，回撤低估和 VaR 低估同样危险。

压力测试部分包括历史情景重放和合成市场冲击。历史情景选取 2020 年疫情、2024 年 9 月政策组合和 2025 年 4 月关税冲击，直接用当时的行业真实收益和沪深 300 收益重算当前组合的损失。合成情景则通过行业 beta 把市场下跌、波动率放大等冲击传导到行业层面。这样既能回答“历史上类似时期会发生什么”，也能回答“如果未来市场再跌 5% 或 10% 会怎样”。

收益归因采用事件日前 60 个交易日的行业收益对沪深 300 做滚动回归，得到每个行业的 beta。对于每个事件窗口，我把行业收益分解为市场 beta 贡献、行业相对收益和事件残余 alpha。风险归因则使用行业日收益协方差矩阵，计算每个行业的 Marginal VaR 和 Component VaR，从而定位哪些行业在组合风险中贡献最大。这样收益和风险两条线都能追溯到具体行业和事件。

风险限额部分不是简单输出一个数字，而是把单一行业权重、HHI 集中度、VaR 违约倍数和组合 VaR 预算做成可配置阈值。系统会自动检查是否超限，并生成 warning 列表。这样风控人员不需要人工逐条核对，可以直接看哪些指标已经进入预警区间。

为了让报告可交付，我使用 Plotly 生成 HTML 风险仪表盘，并通过 FastAPI 暴露风险报告、压力测试、归因报告和配置提交接口。最后，FinMAS-Risk 会把聚合后的风险摘要交给 DeepSeek，生成一段自然语言风控点评，帮助非量化业务人员快速理解当前主要风险。

### Result

FinMAS-Risk 在现有 321 场景结果上稳定生成了完整风控报告。风险回测显示，事件级 VaR 在长周期上明显低估了尾部风险：T+1 违约率为 9.35%，T+5 为 12.15%，T+20 达到 19.00%，而理论目标只有 5%。Kupiec 检验在三个期限上均被拒绝，说明原模型的风险分布过于乐观，尤其是 T+20 的尾部风险需要额外校准。

压力测试结果显示，2020 年疫情情景下组合亏损约为 9.41%，2025 年关税情景下约为 6.50%，市场单日下跌 5% 和 10% 时组合亏损分别约为 3.81% 和 7.62%。风险归因进一步表明，行业 801790、801180、801750、801780 和 801080 是组合 VaR 的主要来源。这些结论不是停留在代码层面，而是可以直接用于解释“当前组合最怕什么、最可能在哪里亏钱、历史类似情景下会亏多少”。

最终模块输出 JSON、CSV、HTML 和 API 四种形式，形成了从数据读取、风险计量、压力测试、归因分析、限额预警到自然语言点评的完整闭环。这个模块完全离线运行，不依赖重新训练，因此可以快速复现，也适合作为风控中心实习经历中的核心成果。

## 四、简历可直接使用的主项目叙事

FinMAS 是一个面向中国 A 股宏观政策事件的多智能体金融分析系统。项目背景是传统时序模型难以理解低频政策事件，而单纯使用大模型判断行业涨跌又缺乏证据可追溯性和严格防泄漏能力。我负责从系统架构、机理推理、RAG、时序模型、LLM 接入到 walk-forward 实验的整体实现。

在机理层面，我设计了基于 RAT 和知识图谱的 Mechanism Agent，使每个事件都沿着社会、行业、公司和资产四个层级逐步推理，并强制引用事件日前可见文档。在数据层面，我实现了 Informer 与 KF-Transformer 双分支模型，通过门控融合和 Conformal Prediction 输出点预测与区间。在工程层面，我统一了 DeepSeek 和 Ollama 的调用接口，加入线程池并发、GPU 训练和断点续跑，使系统能够稳定完成大规模实验。

最终系统在 321 个事件-行业场景上完成 walk-forward 回测，严格排除未来数据后方向准确率达到 51.09%，相比留一法基线 47.62% 有明显提升。这个结果说明系统在更诚实的评测框架下仍然具备信息增量，而不是依赖数据泄漏获得虚高准确率。

## 五、简历可直接使用的 FinMAS-Risk 实习叙事

> `【FinMAS-Risk / 风控中心实习】`

在金融科技风险监控中心，我负责完善 FinMAS 系统的风险评估模块，新增 FinMAS-Risk。原有系统主要输出事件级预测风险，但缺少行业级、组合级风险视图，也无法满足压力测试、限额监控和风险归因等风控业务需求。我的任务是在不重新训练模型的前提下，基于已有实验数据和原始市场数据构建离线风控分析服务。

我实现了事件级、行业级和组合级风险聚合，覆盖 T+1、T+5、T+20 三个期限，并支持历史模拟、Bootstrap、参数法、EWMA、极值理论和模型区间等多种风险计量方法。通过 Kupiec、Christoffersen、Pinball 和 Bootstrap 回测，我发现原有事件级 VaR 在长周期上低估尾部风险，T+20 实际违约率达到 19.00%，远超 5% 的理论目标。这一发现说明模型需要对远期风险做期限依赖校准。

在压力测试方面，我实现了历史情景重放和合成市场冲击。历史情景包括 2020 年疫情、2024 年 9 月政策组合和 2025 年 4 月关税冲击；合成情景包括市场下跌 5%、10% 和波动率放大。压力测试结果显示，疫情情景下组合亏损约 9.41%，关税情景下约 6.50%。在风险归因方面，我使用 60 日滚动 beta 进行市场、行业和事件 alpha 分解，并通过 Component VaR 和 Marginal VaR 定位行业风险来源。

为了让风控结果可交付，我使用 Plotly 生成 HTML 风险报告，并通过 FastAPI 提供风险报告、压力测试和归因报告接口。系统还接入 DeepSeek，对聚合风险摘要生成自然语言点评，使非量化业务人员也能快速理解风险来源。最终，FinMAS-Risk 形成了从风险计量、校准、压力测试、归因、限额预警到报告输出的完整闭环。

## 七、技术栈

FinMAS 主系统使用 Python 作为主要开发语言，深度学习部分基于 PyTorch，LLM 接入支持 DeepSeek API 和本地 Ollama。RAG 层使用 BGE-large-zh-v1.5、FAISS 和 BM25，时序模型包括 Informer、KF-Transformer 和 GatedFusion。实验管理采用 walk-forward 时间防火墙、GPU 并发和断点续跑。

FinMAS-Risk 使用 pandas、NumPy、Plotly、FastAPI 和 Uvicorn。风险模型覆盖历史模拟、Bootstrap、参数法、EWMA 和 EVT。数据来源包括行业日线、沪深 300、LPR、融资余额和行业估值数据。最终输出 JSON、CSV、HTML 和 API 四类交付物。
